# ResearchClawEval 科研 Agent 框架竞赛

> **用你自己的 research-agent 框架，在 3 个真实科研任务上跑出结果，由主办方统一评分。**
>
> 报名开放 · 赛期一个月 · 评测口径完全公开

---

## 一、背景：自动化科研到了需要一把统一尺子的时候

过去两年，科研自动化从概念走到了能跑通全流程。

多个科研自动化项目已经展示了从选题、写代码、做实验到成稿的端到端流水线；此后一批框架相继出现，各自宣称自己的"科研闭环"更强。

与此同时，一个更实际的问题浮现出来：

> **这些框架到底谁更强？**

**现在的答案是：没法比。**

每个框架自带一套演示、一套指标、一套算力预算。你在 A 框架的 README 里看到的成绩，和 B 框架报告的成绩，**根本不在同一个尺子上**：

- 任务不同（有的跑分类，有的跑训练，有的跑强化学习）
- 数据集不同（甚至同一个 benchmark 用了不同的切分）
- 预算不同（跑 2 次实验和跑 45 次实验的结果没法并排）
- 评分者不同（自评、人工看、还是 LLM 判？）

本竞赛要解决的就是这件事：**把变量收敛到只剩一个——你的框架本身。**

---

## 二、我们做了什么

ResearchClawEval 是一个面向科研 Agent 框架的**公开评测控制层**。它把评测里所有能固定的东西都固定下来：

| 固定项 | 说明 |
|---|---|
| **任务契约** | 每个 topic 一份，写明题目、指标、数据可见性、算力预算 |
| **数据切分** | 冻结并公示 sha256，任何重新划分都会被识破 |
| **官方评分器** | 同一份代码、同一份数据，对所有参赛者一视同仁 |
| **模型** | 自测阶段自带（推荐模型见规则 §4）；正式测评由主办方统一注入——**这不是模型竞赛，是框架竞赛** |
| **实验次数** | 2–4 次，写进契约 |
| **运行环境** | 统一的 runner 与容器隔离 |

**唯一剩下的变量，是你的框架。**

评测口径完全公开：契约、数据、评分器、切分全部可见——你可以在提交前无限次自测，不需要信任任何一方。

## 三、任务（Task）

三个**真实的科研任务**，不是玩具 benchmark。全部公开、全部可自测。

| Subtask | 任务 | 官方指标 | 数据 |
|---|---|---|---|
| **TDC-ADMET-Tox** | 从分子结构预测三种毒性终点（AMES / hERG / DILI） | macro-AUROC ↑ | 1.4 MB |
| **PsyDefDetect** | 从支持性对话中识别心理防御机制（8 类） | macro-F1 ↑ | 5.4 MB |
| **ARC-WBE-2026** | 从 Transformer 的权重矩阵估计逐层激活 | 调整后分层得分 ↓ | 907 MB |

三者跨了**表格/分子、文本分类、数值估计**三个不同领域——你的框架不能只擅长其中一种。

**数据不进仓库，但也不需要你自己找**：一条命令下载 + 校验 sha256。

```bash
bash scripts/setup_datasets.sh --dataset tdc_admet_tox
bash scripts/setup_datasets.sh --dataset psydefdetect
bash scripts/setup_datasets.sh --dataset arc_wbe_2026
```

## 四、参赛要做什么

**你只写一个文件。**

一个 wrapper/adapter，声明"怎么启动你的框架"。它不含任何评测逻辑——选题、实验设计、执行、比较、选择、成稿，**全部由你的框架自己负责**。

从 `templates/example-adapter/` 复制骨架，填好 5 处 TODO（框架名、入口命令、容器镜像、任务输入形态、原生日志标记），跑：

```bash
export RUN_ROOT=/tmp/my-run
bash scripts/runner/<your-id>_<your-framework>_<topic>_fullrun.sh
```

跑完你会得到：研究计划、实验轨迹、最终报告、完整日志，以及topic 对应的分数——psydef 可立即用本地评分器自测出分；tdc/arc 的官方分由主办方在提交后统一给出（规则 §6.1）。

**完整流程见 [`docs/participant_quickstart.md`](participant_quickstart.md)。**

## 五、提交什么

**一个开源仓库**（你的框架）+ 每个 subtask 一份运行产物：

```
workspace/
  research_idea.json       研究思路（必须在第一次实验前锁定）
  experiment_trace.json    实验轨迹（每次实验与其结果）
  final_report.md          最终报告
  <subtask 载荷>            预测文件 / 估计器
logs/e2e.log               完整执行日志
prompt.txt                 你喂给框架的任务输入原文
PROVENANCE.json            溯源信息（模型、提交号、数据 sha256）
```

## 六、怎么评分

### 6.1 只用客观分

**排行榜上的每一个数字，都由主办方的官方评分器在同一份数据上算出。**

不接受自报分数——占位符分数、自算指标、错误切分这三类自报都是不受理事由。

| Subtask | 官方指标 | 方向 |
|---|---|---|
| TDC-ADMET-Tox | macro-AUROC | 越大越好 |
| PsyDefDetect | macro-F1 | 越大越好 |
| ARC-WBE-2026 | 调整后分层得分 | 越小越好 |

### 6.2 怎么排名

**主榜是三个 subtask 各自的排名，不做跨任务合并。**

原因很实在：三个指标量纲完全不同——AUROC 在 0.5–1.0 之间，macro-F1 大概 0.1–0.3，arc 的得分跨了十几个数量级。**任何把它们归一化后相加的做法，结果都会被校准伪影主导，而不是被框架质量主导。**

所以：

- 每个 subtask 一列，各自排名
- **你在哪个任务上强，就在那一列上体现**
- 不设"总分冠军"——那会制造一个虚假的综合性

### 6.3 并列怎么处理

分数相同或差距小于公示阈值的，标为并列，不硬排。阈值由主办方实测标定后公示。

## 七、规则

### 允许

三个任务全部公开，**你可以在提交前无限次调试**。这是刻意的设计：门槛低、可复现、可自测。

**我们不会假装能划清"调框架"和"针对性适配"的界线。**

### 禁止

| | |
|---|---|
| **提交后不得修改框架** | 三个 subtask 必须用同一版本 |
| **不得自带模型或 API endpoint** | 正式测评阶段模型由主办方统一注入，会核对（自测阶段自带，见规则 §4） |
| **`prompt.txt` 不得规定方法** | 算法族、特征表示、架构、超参、实验顺序、选定方法——都由你的框架自己定 |
| **框架不得包含针对这三个任务的先验** | 例如"在分子任务上优先用某某指纹"——主办方会读源码 |
| **不得重新划分数据** | 切分 sha256 必须逐字匹配 |

**跑不出产物 = 不受理。** 这是硬门槛。

### 原生执行

runner 要求你的框架**从自己的执行里**打印一个标记。跑完了但日志里没有它 → 判为非原生执行，不计分。这是为了防止"人工代跑后包装成框架产物"。

## 八、时间线


## 九、跟 SemEval 学的地方

这套赛制借了 [SemEval](https://semeval.github.io/) 共享任务（Shared Task）的几条做法，因为它们确实有效：

| SemEval 的做法 | 我们的对应 |
|---|---|
| 任务先行，评测口径完全公开 | 3 个 subtask 契约 + 官方评分器全部公开 |
| 组织者集中评分，所有人同一把尺子 | 主办方统一跑评分器 |
| 提供 baseline，起步有参照 | 参照实现与示例适配器公开，可当起点 |
| 明确阶段与硬截止 | 报名 → 开发 → 提交 → 公布 |
| 提交物尽量简单 | run 产物 + 仓库，**不需要你重写框架** |

**一处不同**：SemEval 的参赛者提交的是"系统"，这里提交的是**整条科研流程**——从选题到成稿。这既是难点，也是这个竞赛真正想测的东西。
