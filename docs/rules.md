# ResearchClawEval 科研 Agent 框架竞赛 — 规则

> 本文件是**比赛的规则**。长期社区榜（12 维评测）是另一件事，见 §1 与附录 A。
>
> 修订记录：v2 初稿把"12 维"写进了比赛，与"比赛只出客观分榜"的决定冲突，已改。

---

## §0 定位

> **用你自己的 research-agent 框架，在 3 个公开科研任务上跑出结果，由主办方统一评分排名。**

**为期一个月。** 评测口径完全公开：契约、数据、评分器、切分全部可见。

**本比赛不主张泛化性。** 三个 topic 公开、可无限调试，这是刻意选择（门槛低、可复现、可自测）。代价是榜测的是"**在这 3 个已知公开任务上谁做得更好**"。认可这一点的队伍再参加——规则里不会假装我们在测别的东西。

## §1 两层结构

| | **比赛** | 长期社区榜 |
|---|---|---|
| 周期 | **1 个月** | 常年开放、持续维护 |
| 交什么 | run 文件 + 产物 | 同左，或更完整的包 |
| 评什么 | **客观分**（官方分） | 客观分 **+ 12 维** |
| 用于 | 产生第一批上榜结果 | 承接比赛之后的一切 |

**比赛不是论文的一部分**，它是这个项目的推广活动。

## §2 赛道与参赛

| 项 | 规定 |
|---|---|
| 赛道 | 单赛道 |
| 参赛单元 | 一个 research-agent 框架 |
| topic | **3 个，全部公开**：`tdc_admet_tox` / `psydefdetect` / `arc_wbe_2026` |
| 交付物 | **开源仓库**（框架源码）+ 每个 topic 一份产物（§5） |
| 模型 | 自测自带、正式测评由主办方统一提供（§4） |
| 实验次数 | **2–4 次**，按"策略线"计（见 §5.8），不额外限定 |

**不设隐藏集，也不宣称保密。** 参赛者可以在提交前无限次调试——这是设计，不是漏洞。

## §3 数据

### 3.1 三个 topic 都是公开 benchmark

| topic | 来源 | 大小 | 许可 |
|---|---|---|---|
| `tdc_admet_tox` | Harvard Dataverse `doi:10.7910/DVN/21LKWG` V105 | **1.4 MB** | Dataverse 条款 |
| `psydefdetect` | HuggingFace `AIMH/PsyDefConv` | **5.4 MB** | `cc-by-nc-4.0`（非商业） |
| `arc_wbe_2026` | HuggingFace `aicrowd/arc-whestbench-public-2026` | **907 MB** | `cc-by-4.0` |

✓ `psydefdetect` 许可已核查：本竞赛按**非商业用途**举办，该 topic 保留；数据使用须遵守 `cc-by-nc-4.0`。

### 3.2 交付方式：下载说明 + sha256，不发数据包

主办方**不重新分发数据**。参赛者自己下载、自己校验：

```bash
bash scripts/setup_datasets.sh --dataset tdc_admet_tox
bash scripts/setup_datasets.sh --dataset psydefdetect
bash scripts/setup_datasets.sh --dataset arc_wbe_2026
```

脚本会从原始公开发布处下载并校验 sha256 后才接受。期望值（可自行核对）：

| 文件 | sha256 |
|---|---|
| `admet_group.zip` | `bd0005246cb6f1672333c28ad202112a8bf071ab65d847848715030308faf1f1` |
| `PsyDefConv.json` | `88d55e1ae6f4653661baa795166ef103f5439f4d6720b1767c3be7bbc3904ad7` |

> 部分网络下 `huggingface.co` 会被 DNS 污染。设 `HF_ENDPOINT=https://hf-mirror.com`——脚本内置镜像回退，但只在直连失败后启用。

### 3.3 切分冻结

**主办方冻结并公示每个 topic 的切分文件 sha256。提交包里的 `split_sha256` 必须逐字匹配，不匹配即不受理。**

这不是形式条款——同一份预测在不同划分上算出的分数不可比，故 `split_sha256` 逐字匹配是硬校验。psydef 的 canonical 划分 sha256 为 `2fa82b8f921bd135fb7c6e6dc4f97e95209c84f4613d402602e8cccb9942ccb9`。

**psydef 用的是对话级无泄漏切分**（train 1875 / eval 461，对话 160/40，交集 0）。
该数据集的官方切分是记录级的（test 记录的对话出现在 train 中是它的既有性质）——本比赛不用官方切分。

切分文件随本仓发布，可自行核验：

| 文件 | sha256 |
|---|---|
| `psydefdetect_split.canonical.json` | `2fa82b8f921bd135fb7c6e6dc4f97e95209c84f4613d402602e8cccb9942ccb9` |
| `tdc_admet_tox_split.canonical.json` | `83bc2a1b6c451adc7da1a31efd550388051abbc9cc912ff9328c9104c17a7ad7` |

arc 无独立 canonical 文件——其可见验证集/评分集切分随数据集生成（`setup_datasets.sh`），sha256 记录在 `<dataset root>/split_manifest.json` 并按 `mlp_id` 互斥。

### 3.4 arc 的可见验证集

arc 是唯一不给框架真值的 topic——官方指标要比对真激活，而真激活在主办方侧。**没有可自评的数据，框架的 `experiment_trace.json` 里就不会有逐轮性能数字**，`b0`/`bT` 无从计算（无真值时二者通常不可得）。

所以 arc 提供一个**可见验证集**：100 个 MLP 中切出 10 个（含真值）给框架自评，其余 90 个是评分集，两者按 `mlp_id` 互斥。`setup_datasets.sh` 会自动生成。

**框架必须把每次实验的自评结果记为数字**（`n_mlps`、`adjusted_final_layer_score`、`final_layer_mse`、`all_layers_mse`）；写一句定性描述不算。

## §4 模型

**两阶段、两种供给**：

| 阶段 | 模型来源 | 说明 |
|---|---|---|
| **自测阶段**（提交前，可无限次迭代） | **参赛者自带** | 主办方不干预、不限制；推荐 `deepseek-v4.1-flash` 作为自测首选（组织方建议，不强制；你也可以用自己熟悉的其他模型） |
| **正式测评**（提交后，主办方统一评分） | **主办方统一注入** | 经 `OPENAI_BASE_URL / OPENAI_API_KEY / OPENAI_MODEL` 注入；框架不得自带模型或 base_url |

通用规则（两阶段一致）：

| 规则 | 说明 |
|---|---|
| 代码不得硬编码 endpoint 或模型 ID | 模型访问一律走环境变量：自测阶段设你自己的值，正式测评阶段由主办方覆盖 |
| 模型 ID 由主办方公示，**大小写敏感** | 写错会报 `no healthy deployments` |
| **正式测评禁止自带模型或自带 base_url** | `framework_internal_model` 与公示值不符即不受理 |
| `framework_internal_api_base_url` 一并核对 | 两个字段都是现成的 trace 契约 |

## §5 提交物

### 5.1 仓库

开源仓库，含框架源码与可复现说明。**主办方会读源码**（§7）。

### 5.2 产物（每个 topic 一份）

```
<framework>-<topic>-<YYYYMMDDTHHMMSS>/
├── PROVENANCE.json          # framework_commit / model / dataset_sha256 / split_sha256
├── workspace/               # 名字逐字保留
│   ├── research_idea.json   # 必需，须在第一次实验前锁定
│   ├── experiment_trace.json# 必需
│   ├── final_report.md      # 必需
│   └── <topic 载荷>          # 见 5.3
├── logs/
│   └── e2e.log              # 必需：运行时的原始 stdout/stderr 流
├── prompt.txt               # 必需：喂给框架的任务输入原文
└── source/                  # 建议：框架生成的研究代码
```

**日志必须落在 `logs/e2e.log`。** 判官只认 `logs/e2e.log` → `logs/native.log` → `logs/native_stdout.log`，**不读根目录的 `run.log`**。

### 5.3 逐 topic 载荷

| topic | 载荷 | 格式 |
|---|---|---|
| `tdc_admet_tox` | `predictions.csv` | `sample_id,endpoint,probability` |
| `psydefdetect` | `predictions.jsonl` | 每行 `{"id":…, "predicted_label":…}` |
| `arc_wbe_2026` | `estimator.py` | 暴露 `predict(mlp)`，返回 `(32,256)` NumPy 数组 |

### 5.4 必须用主办方的 runner 跑

用 runner 模板生成的 `<framework>_<topic>_fullrun.sh` 运行，不要用自己写的编排（见 `scripts/runner/` 模板与 `docs/participant_quickstart.md`）。

理由：`logs/e2e.log` 由主办方侧代码产出，格式与内容不受参赛者控制。**这不是绝对保证**（见附录 A），但比一份手写的日志强得多。

### 5.5 原生执行标记（最容易踩）

runner 要求**框架从自己的执行里**打印 `FRAMEWORK_NATIVE_LOG_MARKER`。

```
exit 0 但日志里没有这个标记  →  判为「非原生」，不计分
```

标记要放在最前面——这样即使后面挂了，这次运行仍可归因。

### 5.6 `sample_id` 必须逐字对得上

`tdc_admet_tox` 的 id 规则：

```
{endpoint.upper()}_{tv|test}_{归档行号}
```

**hERG 的 `endpoint` 列是小写 `hERG`，但 id 前缀是大写 `HERG`。** 用 `endpoint` 原值拼会得到 `hERG_test_000000`，而主办方的隐藏标签里是 `HERG_test_000000` —— **一行都匹配不到，分数为零**。

**正确做法：直接用 `public/test.csv` 里的 `sample_id` 列，不要自己拼。**

### 5.7 `prompt.txt`

主办方提供统一的任务输入（契约 + 预算 + 任务摘要），**由 runner 生成并挂载到 `$WORKSPACE/input/prompt.txt`**（`scripts/runner/` 模板用契约 + 执行预算 + 任务摘要合成；正式测评时任务摘要由主办方提供，自测时在模板里填 `PROMPT_TASK_SUMMARY`）。**怎么把它翻译成自己框架能吃的形态，由参赛者负责**——这正是 `adapter` 的含义。提交物里的 `prompt.txt` 就是你那份挂载后的文件，`prompt_sha256` 对它计算——自测口径与正式测评一致。

| 规则 | 依据 |
|---|---|
| prompt **不得规定方法**：算法族、特征表示、模型架构、超参、实验顺序、选定方法 | `ideation_policy.forbidden_host_constraints` |
| 主办方用上述清单扫 prompt，命中即不受理 | 本规则 |

### 5.8 实验计数：策略线

"2–4 次实验"按**策略线**计数——这是为适配树搜索等"节点多、路线少"的框架形态而定的语义：

- 一条**策略线** = 一套**实质性不同**的实验路线：在算法族、特征表示、模型架构、或超参搜索空间整体设定中至少一维有别的配置簇；
- 同一条线内的**重试、仅换种子（seed-only repeat）、小调参不算新实验**；种子重复不算 materially different（与 TDC 预算口径一致）；
- 一条线只有**完成了至少一个完整配置**（在固定验证切分上完成训练与评估、产出指标与产物）才算确立；
- **失败的 setup 尝试不计入名额**（未训练/未评估的尝试只记入日志）；已训练并评估、但随后崩溃或**超时**的配置，按其所属策略线计为一个完成配置；崩溃/超时节点本身**不新开策略线**；
- 上限 **4 条**不同策略线，下限 **2 条**；任何时刻不得着手第 5 条。

壁上时间的硬约束只存在于 TDC 契约（累计实验 3,600s / 总墙钟 7,200s）；psydef/arc 的预算以各自契约与执行预算为准。

## §6 评测与排名

### 6.1 谁评

**主办方评。** 参赛者自评只用于自己迭代，**自评分不入榜**——占位符分数、自算指标、错误切分这三类自报都是不受理事由。

### 6.2 评什么：**只用客观分**

比赛榜 = 每个 topic 的**官方分**。由冻结的官方评分器在测试集上算出，参赛者不可能自报。

| topic | 官方指标 | 方向 |
|---|---|---|
| `tdc_admet_tox` | `macro_average_auroc` | ↑ |
| `psydefdetect` | macro-F1（正类 1–8） | ↑ |
| `arc_wbe_2026` | `adjusted_final_layer_score` | ↓ |

**判官那套（7 维语义评分 + ED）不进比赛榜**——它需要 LLM，有噪声、有成本，而且在本比赛的交付模式下会退化成"给参赛者自己交的证据打分"（附录 A）。它属于长期社区榜。

### 6.3 排名

**主榜是三列，逐 topic 排名，不做跨 topic 合并。**

原因：三个指标量纲完全不同（AUROC 0.5–1.0 / macro-F1 约 0.1–0.3 / arc 是 1e-4 到 1e-9 量级）。任何跨 topic 归一化都会被校准伪影主导，排名结果会由指标的量纲区间而非框架质量决定。

**参赛者三列各自有名次**，不设"总冠军"。

## §7 防止针对性适配

### 7.1 先说清楚：允许什么

三个 topic 全部公开，参赛者**可以**在提交前反复跑、反复改框架。**这是允许的也是预期的**——不存在"针对性微调"与"调框架"的可操作界线，所以本比赛不假装能划清。

### 7.2 禁止什么

**框架不得包含针对本比赛这 3 个任务的先验。** 例如：

| 允许 | 禁止 |
|---|---|
| "优先尝试简单模型，失败再考虑复杂模型" | "在分子性质预测上优先用 Morgan 指纹 + LightGBM" |
| "分类任务先检查类别不平衡" | "psydef 的 eval 只有 461 条，所以要……" |
| 通用的实验设计启发式 | 把这三个数据集的名字、规模、指标量级写进代码 |

### 7.3 检测

**主办方读提交的源码。** 无自动化手段，靠人工审查。

**查出即取消资格。**

> ⚠️ 这条规则的强度等于实际审查的力度。不读，等于没有这条规则。

## §8 不受理的情况

| 触发 | 后果 |
|---|---|
| **跑不出产物** | 不受理（硬门槛） |
| `dataset_sha256` / `split_sha256` 与公示值不符 | 不受理 |
| `framework_internal_model` 与公示模型不符，或自带 base_url | 不受理 |
| `prompt.txt` 规定了方法 | 不受理 |
| 分数为占位符 / 常量 | 不受理 |
| 用非官方 metric 自算分数入榜 | 不受理 |
| 命中 `forbidden_native_entrypoint_tokens`（如 `codex exec`） | 判非原生 |
| 框架含针对这 3 个任务的先验（§7.2） | 取消资格 |

## §9 时间线

**比赛为期一个月。关键在于赛前必须全部就绪**——那一个月是给参赛者的，不是给主办方的。

```
赛前        契约冻结 · 数据可下 · 评分器跑通 · 文档 · 榜单页面 · 参照实现公开
            ← 出口条件：**外人照文档能独立跑通一个 topic 并拿到分数**
第 1 周      报名 + 环境接入
第 2–3 周    开发与自测
第 4 周      提交窗口 → 主办方评分 → 公布
```

**第 1 周是最危险的一周。** 参赛者若卡在环境接入上，整个月就废了——所以赛前的"外人试跑"不是可选项。

## 附录 A：长期社区榜（12 维）

比赛结束后承接，常年开放。**与比赛用的同一套 harness、同一批 topic、同一套切分**，只是评测维度更多。

12 维：`b0 / bT / AUP / UR / ED` + 七维判官 `PQ / PEA / ER / OU / ECC / SC / CC`。

**比赛不用它的三条理由：**

1. **成本**：七维判官里 `er`/`sc`/`cc` 走容器 agent，约 47K tokens / 次运行。比赛要求跑不出产物即不受理，再叠这个成本，门槛会挡住大部分队伍。
2. **噪声**：单次调用路径的实测底噪是平均绝对差 0.052、84% 一致。比赛要排名，需要先标定并列阈值，而那是另一件工程。
3. **⚠️ 最关键**：判官的输入提示词写着——

   > `e2e.log` —— **宿主抓取的**端到端执行日志，**框架改不了它**
   > 报告和计划是框架自己写的，**日志才是宿主记录的事实**。两者冲突时以日志为准。

   **在"参赛者自己跑、自己交产物"的交付模式下，日志不再由宿主抓取。** 这个前提不成立。因此 `ER`/`SC`/`CC` 实际测的是**提交证据的质量**，不是执行本身。

   > 一个把日志写得漂亮、引用得体的参赛者，这三项会很高，不管实际执行是否真那么稳。
   > **这是已知局限，不是 bug** —— 但对外不能说"我们测了执行稳健性"。

**其余口径**（社区榜适用）：

- `AUP` 有 `1/N` 地板，**不跨 topic 平均**；报任何 AUP 必须同时报 N
- b0/bT 经固定锚点归一（见 `scoring/metric_anchors.json`，arc/psydef/tdc 三个 topic 的约定标定——**锚点是约定格式，不是权威基线**）
- 锚点让 0 有明确语义（= 与随机同水平），**缺失格不能用 0 填充**，记 `null`
- `CC` 是 framework-relative（判官从运行自身推导义务清单），**跨框架不可比**——要么改成主办方下发统一阶段契约，要么降为展示列
- 判官模型整个周期冻结并公示
